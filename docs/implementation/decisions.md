# Implementation decisions

Material choices made while building V1. Architecture-level decisions live in [`../architecture/decision-log.md`](../architecture/decision-log.md); this file records implementation choices and documented deviations.

| ID | Decision | Why | Revisit when |
| --- | --- | --- | --- |
| IMP-001 | Node 24.21.0 LTS (`.nvmrc`), pnpm 10.34.7 via `packageManager`, TypeScript 6.0.3 strict (`exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`). | Current Vitest 5, ESLint 10 and Testcontainers 12 need Node ≥ 22.22. TypeScript 7 (native) is not yet supported by typescript-eslint (< 6.1). pnpm 11 needs Node ≥ 22.13 and was avoided for toolchain stability. | typescript-eslint supports TS 7. |
| IMP-002 | Internal packages export TypeScript source directly (`exports: ./src/index.ts`); `tsx` runs the API/worker, Next transpiles for the web, esbuild bundles Lambda handlers in CDK. | No build step or `dist/` drift between packages. | A package is published outside the monorepo. |
| IMP-003 | Zod 4 schemas in `@shinrai/contracts` validate every command, event, API body and agent tool input/output. | One strict schema per boundary, shared by server, worker, web and agent tools. | — |
| IMP-004 | Money is integer credit-cents (1 credit = 100); prices are integer cents 1–99; quantities are whole contracts. | No floating point in the ledger. A winning contract pays exactly 100. | — |
| IMP-005 | One binary book per market. `BUY YES @p` crosses a resting `BUY NO @q` when `p + q ≥ 100`; each fill mints a YES/NO pair. The maker pays its limit, the taker pays `100 − maker` and is refunded the improvement. | Escrow then always holds exactly 100 per matched pair, which makes settlement a provable drain-to-zero. | Sell-to-close is required. |
| IMP-006 | **No sell-to-close in V1.** Positions are held to settlement; open orders can be cancelled. | Smallest correct trading surface for one market loop. `ponytail:` ceiling is documented here. | A strategy needs to exit before resolution. |
| IMP-007 | Price-time priority: best maker price, then a per-market monotonic `sequence` assigned under the market lock. Self-matching is allowed. | Deterministic, explainable tie-breaks. Paper credits make self-matching harmless; it stays balanced. | Multi-tenant competitive scoring. |
| IMP-008 | One shared `executeCommand` (idempotency → pure decide → one event → atomic commit) used by both `InMemoryExchange` and the PostgreSQL store. | Unit/evaluation tests exercise the exact production command path; adapters only differ in persistence. | — |
| IMP-009 | Every command produces exactly one outbox event. A rejected command writes only an audit row, an idempotency record and a `command.rejected` event; never orders, reservations, fills or ledger rows. | Satisfies "rejections change no order-book/ledger state" while keeping blocked actions visible in the activity feed. | — |
| IMP-010 | Rejections are stored under their idempotency key and replayed. A reused key with a different payload returns `IDEMPOTENCY_CONFLICT` (not stored). | Retries are safe and deterministic; callers use a new key for a new intent. | — |
| IMP-011 | `ResolveMarket` is exactly-once at the business level: a second resolution with the same outcome (any key) returns the original `market.resolved` event with `replayed: true`; a different outcome is `RESOLUTION_CONFLICT`. | Worker retries can never pay twice. | — |
| IMP-012 | Agents can never open markets, grant credits or resolve markets, enforced in the domain (`actor.kind`) in addition to API scopes. | Defense in depth. | — |
| IMP-013 | **Temporal is not used in V1.** Replay/evaluation run as an explicit command (`pnpm demo:replay`, `POST /replays`). | The goal's local stack is PostgreSQL + NATS only; nothing in V1 waits long enough to need durable workflows. | Human approvals or scheduled replays need durable waits. |
| IMP-014 | **Redis and MinIO are not used.** Replay reports go to the filesystem (`var/reports`). | No V1 feature needs them. | Measured need. |
| IMP-015 | Local bearer tokens (`SHINRAI_DEV_TOKENS`) map to principals with scopes. The browser uses a local-only operator token from `NEXT_PUBLIC_OPERATOR_TOKEN`. The API refuses dev tokens when `SHINRAI_PROFILE=aws`. | Consistent scoped authorization without an identity provider in V1. The token is a local identity, not a secret. | A hosted demo needs real users (Cognito/IAM). |
| IMP-016 | Read-only Polymarket comparison adapter: **deferred, not implemented.** | Optional per the goal; V1 correctness must not depend on it. | All V1 gates are green and comparison views are wanted. |
| IMP-017 | The market lock is `pg_try_advisory_xact_lock` inside the SERIALIZABLE transaction. On "busy" the transaction rolls back and re-queues with a short jitter, using a separate 10s lock-wait budget instead of the 8-attempt serialization-retry budget. Accounts are then locked `FOR UPDATE` in sorted id order. | Found by `postgres-concurrency.test.ts`: a blocking `pg_advisory_xact_lock` as the first statement fixes the SERIALIZABLE snapshot *before* the wait, so the winner of the lock reads stale data and fails with 40001. 30 concurrent orders exhausted 8 retries. Try-lock means the snapshot is taken after the lock is held. | Lock contention is high enough that polling costs measurable latency (then use a session-level lock acquired before `BEGIN`). |
| IMP-018 | Local compose Postgres listens on host port **55432** (`SHINRAI_PG_PORT` overrides). | A natively installed PostgreSQL on 5432 is common (it was present on the build machine) and silently intercepts connections. |
| IMP-019 | AWS profile: one CDK stack, 4 Lambdas (API, agent gateway, projector, outbox relay) each with its own role; only the agent gateway may read `/shinrai/openai-api-key`. Optional RDS uses isolated subnets plus single-AZ interface endpoints (Secrets Manager, EventBridge) instead of a NAT. | Least privilege and no NAT. The two endpoints cost money while they exist, so RDS stays off by default. |
| IMP-020 | `infra/cdk` disables `exactOptionalPropertyTypes` only; all other strict flags stay on. | `aws-cdk-lib` declarations are incompatible with that flag. |
| IMP-021 | Hosted (aws profile) authentication is **not implemented**: dev tokens are refused, so a deployed API would answer 401 on every scoped route until an identity provider is added. | Keeps a misconfigured deploy closed by default; real users are out of V1 scope. |
